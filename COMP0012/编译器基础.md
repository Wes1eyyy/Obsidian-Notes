## 2. Regex 与 Lexical Analysis

这是每年都可能考的题型。

你需要掌握：

1. 给定自然语言 specification，写 regular expression。
    
2. 处理边界条件：
    
    - 不能以某字符开头/结尾；
        
    - 某字符不能连续出现；
        
    - 大小写敏感；
        
    - 可选 AM/PM；
        
    - 数字范围限制。
        
3. 能解释 regex 为什么匹配正例、不匹配反例。

**复习重点：**

你要能写出类似：

```regex

```

- `\w` 表示 alphanumeric；
    
- `\d` 表示 decimal digit；
    
- `+`, `*`, `?`, `|`, grouping 的含义；

## 3. NFA / DFA / Thompson / Powerset / DFA Minimisation

这是 Q1 的核心。

你需要掌握：

### 3.1 NFA 与 DFA 基础

会做：

- 根据语言画 NFA；
    
- 给出状态、初态、终态、转移；
    
- 判断一个字符串是否被接受；
    
- 解释 epsilon transition。
    

2024 考过给出识别语言  
`L = { w ∈ (0 | 1 | 2)* | w ≡ 0 mod 3 }`  
的 NFA。

### 3.2 Thompson Construction

需要知道：

- Thompson construction 是把 regex 构造成 NFA 的方法。
    
- `N(s)` 通常表示正则表达式片段 `s` 对应的 **NFA fragment**，不是完整 DFA。
    

2025 直接问了 `N(s)` 表示什么。

### 3.3 Powerset Construction

你必须会手算：

1. 从 NFA 初态开始求 epsilon-closure；
    
2. 对每个输入符号 move；
    
3. 再求 epsilon-closure；
    
4. 得到 DFA state = NFA state set；
    
5. 标记 accepting states；
    
6. 直到没有新集合。
    

2024 要求把一个带 epsilon 的 NFA 转换成 DFA，不需要 minimisation；2025 也考了“设计 minimal NFA 并展示 powerset construction 会产生等价 DFA states”。

### 3.4 DFA Complement

你需要知道：

- 对完整 DFA，可以通过交换 accepting / non-accepting states 得到 complement。
    
- 但前提是 DFA 对 alphabet 是 complete 的；如果缺 transition，要先补 dead state。
    

2025 考过 “You can always complement a DFA. True or False? Justify.”

### 3.5 DFA Minimisation / Moore Table Filling

2024 考过 quotient construction / Moore table filling algorithm 来最小化 DFA，并问需要多少 iteration 到 fixpoint。

你要会：

- 初始划分：final vs non-final；
    
- 根据转移不断 refine partition；
    
- 到 partition 不再变化时停止；
    
- 合并等价状态；
    
- 画 minimized DFA。

# 第二部分：Parsing

## 4. Grammar Ambiguity、Precedence、Associativity

2025 考过表达式 grammar：

```text
E → E + E | E − E | −E | (E) | a
```

问它是否 fit for purpose，如果不是，展示问题并修正。

你需要能判断：

1. 是否 ambiguous；
    
2. 是否有 left recursion；
    
3. 是否表达了运算符优先级；
    
4. 是否表达了结合性；
    
5. 如何改写为分层 grammar。
    

例如表达式 grammar 通常要拆成：

```text
E → E + T | E - T | T
T → -T | F
F → (E) | a
```

如果要 LL(1)，还要继续消除 left recursion。

---

## 5. Left Recursion Elimination

这是高频大题。

2025 考过：

```text
S → Sa | Xx | y
X → z | Sd
Y → Yy | d | ε
```

要求一步一步移除 left recursion，并标明每一步规则。

2024 还考过判断 “Left recursion elimination 是 left factorization 的特殊情况吗？”

你需要掌握：

### 直接左递归

```text
A → Aα | β
```

改为：

```text
A → βA'
A' → αA' | ε
```

### 间接左递归

如果：

```text
S → Xx | ...
X → Sd | ...
```

要先替换，再消除直接左递归。

---

## 6. Left Factoring

需要会把公共前缀提出：

```text
A → αβ1 | αβ2
```

改为：

```text
A → αA'
A' → β1 | β2
```

2024 的 parsing 大题要求对 grammar 预处理成 LL(1)，并要求写清楚每一步 apply 的 operation，例如 left factor、eliminate left recursion。

---

## 7. FIRST / FOLLOW Sets

这是必考能力。

你需要会：

### FIRST

- `FIRST(aα) = {a}`
    
- `FIRST(ε) = {ε}`
    
- 如果 `A → B C`，且 `B` 可以推出 ε，则继续看 `C`。
    
- 如果所有符号都能推出 ε，则 FIRST 包含 ε。
    

### FOLLOW

- `$` 在 start symbol 的 FOLLOW 中；
    
- 若 `A → αBβ`，则 `FIRST(β) - {ε}` 加入 FOLLOW(B)；
    
- 若 `β ⇒* ε`，则 FOLLOW(A) 加入 FOLLOW(B)。
    

2025 考过给 grammar 选择 FIRST/FOLLOW sets；2024 考过计算 FIRST/FOLLOW 并构造 LL(1) parsing table。

---

## 8. LL(1) Parse Table

你要会根据 FIRST/FOLLOW 构造 parse table：

对于 production：

```text
A → α
```

- 对每个 `a ∈ FIRST(α)`，填 `M[A, a] = A → α`；
    
- 如果 `ε ∈ FIRST(α)`，则对每个 `b ∈ FOLLOW(A)`，填 `M[A, b] = A → ε`；
    
- 如果一个 cell 有多个 production，则不是 LL(1)。
    

2025 直接让你判断哪些 rows 是 parse table 的正确行；2024 要求完整构造 LL(1) table。

---

## 9. LR(1) Items 与 Conflicts

2024 和 2025 都涉及 LR(1)。

你需要掌握：

1. LR(1) item 形式：
    

```text
[A → α · β, a]
```

其中 `a` 是 lookahead。

2. Closure 操作：
    
    - 如果 item 中点后面是 nonterminal `B`，则加入 `B` 的 productions；
        
    - lookahead 来自 `FIRST(βa)`。
        
3. Goto 操作：
    
    - 点跨过某个 grammar symbol，形成新状态。
        
4. Conflict 类型：
    
    - shift/reduce；
        
    - reduce/reduce；
        
    - 通常不会有 shift/shift conflict。
        

2025 问了某种 production 形式可能导致什么 LR(1) conflict，以及如何判断 grammar 是否 LR(1)。2024 要求画 start state 和所有 one-hop reachable states，不需要完整 parse DFA。

# 第三部分：Semantic Analysis

## 10. Syntax / Semantics / Context-Free vs Context-Sensitive

这是 Q3 的开头高频选择题/简答题。

你需要掌握：

1. Syntax 决定语言结构，即哪些 words 属于语言。
    
2. Semantics 给语言结构赋予意义。
    
3. Undefined variable 通常是 semantic error，不是 syntax error。
    
4. Parser 基于 context-free grammar，不能完全完成 context-sensitive checks。
    
5. 所有可编译程序的合法性通常不只是 context-free，因为还涉及类型、作用域、声明等上下文信息。
    

2024 和 2025 都考了 semantic analysis 的选择题和 context-free / context-sensitive grammar 判断。

---

## 11. Scope Checking 与 Symbol Table

Revision 明确列出 semantic analysis 包括：

- variables not declared in active scope；
    
- multiple declarations in active scope；
    
- assignment type mismatch；
    
- method invocation parameter number/type mismatch；
    
- incorrect return statements。
    

你要会：

### Symbol Table 操作

- `INSERT`：声明新 identifier 时，插入当前 active table；
    
- `LOOKUP`：从当前 scope 往上找；
    
- 不要向下找。
    

Revision 中特别强调 nested scopes 的 lookup 规则：从当前 scope 开始，向上遍历 hierarchy，直到找到同名 identifier。

### Forward Reference

如果语言允许先使用后声明，通常需要 two passes：

1. 第一遍构造 symbol table hierarchy；
    
2. 第二遍做 scope checking / type checking。
    

---

## 12. Static Binding vs Dynamic Binding

这是近两年都考的重点。

你需要能解释：

### Static binding / static scoping

- 根据 lexical structure 找最近的 enclosing declaration；
    
- binding 在 compile time 决定；
    
- 也叫 deep binding。
    

### Dynamic binding / dynamic scoping

- 根据 runtime call chain 找最近的 active declaration；
    
- binding 在 runtime 决定；
    
- 通常是 shallow binding。
    

Revision 中明确对比了 static scoping 与 dynamic scoping，并用 `foo/bar/main` 的例子说明 static 下两次 `foo()` 都用全局 `b=5`，dynamic 下第二次 `foo()` 会用 `bar` 中的 `b=2`。

**考试常见任务：**

给一段代码，问：

- static binding 输出什么；
    
- dynamic binding 输出什么；
    
- 为什么不同。
    

2024 和 2025 都有这种代码输出题。

---

## 13. Type Expressions

Revision 和 past papers 都很喜欢考。

你要会给：

### Method declaration

例如：

```java
boolean mystery(int[] x, double y)
```

写成类似：

```text
mystery: x: array(int), y: double -> boolean
```

### Class declaration

例如：

```java
public class Cell {
  double[10] val;
  double max;
  Cell next;
}
```

写成类似：

```text
Cell = { val: array(double,10), max: double, next: Cell }
```

Revision 中有类似例子：method declaration 和 class declaration 都要转成 type expression。

## 14. Type Checking 过程

你需要能用步骤解释 semantic analyser 如何发现 type error。

典型流程：

1. 建 symbol table；
    
2. 记录变量/函数声明类型；
    
3. 遍历 AST；
    
4. 对 expression 自底向上推导类型；
    
5. 检查 operator operands 是否符合 typing rules；
    
6. 检查 assignment 左右类型是否兼容；
    
7. 检查 function call argument type/number 是否匹配 parameter type/number；
    
8. 检查 return type 是否符合 method declaration。
    

2024 考了 `goo(int a)` 但传入 `int[10] x` 的错误；2025 考了 `int x = 3; x = x - 0.5;` 中 int 与 real 的赋值/表达式类型错误。

# 第四部分：Intermediate Representation / TAC

## 15. IR 基本概念

Revision 中定义 IR 是 abstract/virtual machine 的 instruction set，位于 decorated AST 和 machine code 之间，用于 language-independent optimisation，例子包括 GIMPLE、LLVM IR、Java Bytecode。

你要会解释：

- 为什么需要 IR；
    
- IR 对多语言、多后端编译器有什么好处；
    
- stack machine IR vs register machine IR 的优缺点。
    

Revision 的练习明确要求比较 stack machine IR 和 register machine IR 的一个 benefit 和 disadvantage。

---

## 16. Stack Machine vs Register Machine

### Stack machine

例：

```text
PUSH 2
PUSH 3
ADD
```

优点：

- 指令短；
    
- 不需要显式寄存器分配；
    
- 编译器生成简单。
    

缺点：

- 栈操作多；
    
- 可能效率低；
    
- 难以直接利用真实硬件寄存器。
    

### Register machine

例：

```text
LOAD R1, 2
LOAD R2, 3
ADD R1, R2
```

优点：

- 更接近真实机器；
    
- 更容易优化；
    
- 数据访问更直接。
    

缺点：

- 需要寄存器分配；
    
- 指令更长；
    
- 编译器复杂度更高。
    

---

## 17. Three Address Code：TAC

Revision 明确：TAC 最多三个地址，形式通常是：

```text
a = b OP c
```

复杂表达式必须拆成多个 temporary，不允许 built-up arithmetic expressions。

你需要会：

1. 把算术表达式翻译成 TAC；
    
2. 把 if / while / repeat-until 翻译成 labels + jumps；
    
3. 处理 array indexing；
    
4. 处理 unary minus；
    
5. 处理 function call / param / return；
    
6. 处理 register machine 风格。
    

past paper 高频表达式：

- `r = -x[i] - 5 * y` 转 triples；
    
- `d = -b - a[i] * c` 转 quadruples；
    
- `repeat { ... } until (n >= 0)` 转 TAC；
    
- `a*a - 2*a*b + b*b` 在 register machine 上生成 TAC。
    

---

## 18. Quadruples / Triples / Indirect Triples

这是必须掌握的表格题。

### Quadruples

形式：

```text
op | arg1 | arg2 | result
```

例如：

```text
uminus | b |    | t1
array  | a | i  | t2
*      | t2| c  | t3
-      | t1| t3 | d
```

### Triples

形式：

```text
address | op | arg1 | arg2
```

结果不再用 temporary name，而是用 instruction address 引用。

### Indirect triples

多一层 pointer list，方便 code reordering，因为移动 pointer 不需要改原 triples 中的地址引用。

2025 Q4 直接问 indirect triples 相比 quadruples 和 triples 的两个优点，并要求解释原因。

---

## 19. Basic Blocks 与 Flow Graph

2025 考过把 TAC statements 分成 basic blocks，并要求 justify。

你需要会：

### Leader 规则

一个 basic block 的 leader 通常是：

1. 第一条 TAC；
    
2. jump target；
    
3. conditional/unconditional jump 后面的下一条语句。
    

### Basic block

从一个 leader 开始，到下一个 leader 前结束。

### Flow graph

- block A 的最后是 jump 到 B，则 A → B；
    
- conditional jump 有两个 successor；
    
- 普通 fall-through 有下一个 block successor。

# 第五部分：Code Optimisation

## 20. 优化总原则

Revision 中明确优化要求：

- Preserve functional behaviour / semantics；
    
- Improve non-functional behaviour，比如 execution time、memory usage、energy consumption。
    

所以你答优化题时要始终写：

> 优化必须保持语义等价，不能改变程序可观察行为。

---

## 21. 必会优化技术

Revision 列出的 common techniques 包括：

- Common Subexpression Elimination；
    
- Algebraic Identities；
    
- Dead Code Elimination；
    
- Constant Folding；
    
- Strength Reduction；
    
- Inlining；
    
- Copy Propagation；
    
- Loop Optimisations。
    

### 21.1 Constant Folding

编译期计算常量表达式。

例：

```text
3 * 5 → 15
2 * PI → precomputed constant
```

收益：减少 runtime computation。  
风险：浮点精度、overflow、语言语义差异。

### 21.2 Common Subexpression Elimination

重复表达式只算一次。

例：

```text
x = a*b + c
y = a*b - d
```

优化为：

```text
t = a*b
x = t + c
y = t - d
```

风险：中间变量被修改、aliasing、side effects。

### 21.3 Dead Code Elimination

删除不会影响结果的代码：

- unreachable branch；
    
- overwritten assignment；
    
- loop/branch 中永远不会执行的代码。
    

2024 和 2025 都考了手动做 dead code elimination。

### 21.4 Strength Reduction

用便宜操作替换昂贵操作。

例：

```text
2 * i
```

可在 loop 中变成递增加法。

Revision 练习明确提到 `2 * i` 可以 reduced to addition。

### 21.5 Code Motion / Loop Invariant Code Motion

把循环中不变的计算移到循环外。

Revision 练习中 `Math.cos(2 * Math.PI + x)` 在 loop 中不依赖 `i`，可以移出循环。

### 21.6 Inlining

把函数调用替换成函数体。

收益：

- 减少 function call overhead；
    
- 暴露更多优化机会。
    

风险：

- code size 增大；
    
- instruction cache pressure；
    
- recursive function 复杂。
    

### 21.7 Loop Unrolling

展开循环，减少 loop control overhead。

收益：

- 减少 branch；
    
- 增加 instruction-level parallelism。
    

风险：

- code size 增大；
    
- cache 变差；
    
- register pressure 增大。
    

---

## 22. 优化识别题

Past papers 喜欢给你：

```java
int x = 5;
int y = 3 * x;
int z = y - 16;
z++;
x = z;
y = x * x * (y + 7);
```

然后给优化后：

```java

int y = 0;

```

你要练习从代码中判断：

- 是否只是 constant folding；
    
- 是否还删除了 overwritten/dead assignments；
    
- 是否涉及 common subexpression；
    
- 是否涉及 inlining。

# 第六部分：Runtime Organisation / Memory

## 23. Runtime Storage Layout

Revision 中 runtime storage 包括：

- Code area：object code，fixed size，read-only；
    
- Static area：fixed address data；
    
- Stack：每个 active procedure 一个 activation record；
    
- Heap：动态分配数据，如 C 的 malloc/free。
    

你要能画/描述：

```text
Code
Static Data
Stack
Heap
```

并说明：

- Stack 存 activation records；
    
- Heap 存 outlive procedure 的对象；
    
- Stack pointer 和 heap pointer 不能 crossing，否则 out of memory。
    

---

## 24. Activation Record

Revision 列出的 activation record 组件包括：

- result / return value；
    
- arguments / parameters；
    
- control link；
    
- return address / saved machine status；
    
- temporaries；
    
- local data；
    
- access link。
    

Past papers 常考：

> Describe three components of an activation record.

你至少要会解释：

### Local data

当前 procedure 的局部变量。

### Control link

指向 caller 的 activation record，用于 return 后恢复调用链。

### Actual parameters

调用 procedure 时传入的实际参数值或地址。

### Return address

procedure 执行完跳回的位置。

---

## 25. Memory Management

Revision 提到手动内存管理问题：

- memory leaks；
    
- dangling references；
    
- double free bugs。
    

Garbage collector 可以减轻 programmer 的 deallocation 负担，但有资源开销、性能影响、可能导致 execution stalls。

2024 考过 explicit dynamic allocation 的两个主要缺点，并要求举例。

你要会写：

### Memory leak

分配后忘记释放，导致内存无法回收。

### Dangling reference

释放对象后仍然通过旧指针访问。

### Double free

同一块内存释放两次，可能导致崩溃或安全漏洞。

- simple code generator；

## 27. RISC vs CISC

2025 考过：

> Describe primary difference between RISC and CISC; generate code for `a = b * 3` in RISC and CISC.

你要会答：

### RISC

- 指令简单；
    
- load/store architecture；
    
- arithmetic 通常只在 registers 上做；
    
- 一条复杂操作要拆成多条简单指令。
    

示例：

```text
LOAD R1, b
LOAD R2, 3
MUL R3, R1, R2
STORE a, R3
```

### CISC

- 指令复杂；
    
- 一条指令可能直接操作内存；
    
- 可以用更少指令表达复杂操作。
    

示例：

```text
MUL a, b, 3
```

具体语法不唯一，关键是体现思想。

# 一句话总结

这门考试不是纯背诵，而是 **“规则型手算 + 概念解释”**。最核心的能力是：给你一个 grammar / automaton / code snippet，你能一步一步变换，并且说明为什么这样做。重点刷 **FIRST/FOLLOW/LL(1)、NFA→DFA、TAC、优化识别、static/dynamic binding、type checking**，这些覆盖了两张 past paper 的大部分高频分值。
